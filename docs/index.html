Time Portal

Time Machine for Arch and Omarchy.

Every backup is a real, browsable btrfs snapshot on an encrypted drive that looks exactly like your machine at that moment — not an opaque archive. Restoring a file is a copy; restoring the machine is a subvolume swap.

🧪 Alpha — still in testing phases. Be careful.

What you get

The four things that make Time Machine Time Machine — a copy-on-write filesystem, hourly incremental deltas, tiered retention, and versions you can actually see — with btrfs in APFS's seat.

🗂️

Browsable snapshots

The backup drive is an ordinary btrfs filesystem. Plug it into any Linux box and read last Tuesday's files with ls and cp — no special software, no repository format.

🔒

Encrypted at rest

LUKS on the drive. A keyfile unlocks it automatically here; a recovery passphrase opens it on a machine that has never seen your keys.

⚡

Incremental & cheap

btrfs send -p moves only the delta, and versions share copy-on-write extents — so many hourly versions stay small.

🧬

Whole-machine fidelity

Ownership, permissions, ACLs, xattrs, symlinks, hardlinks and device nodes — preserved as real filesystem state, not a userspace copy.

♻️

Restore in place

Copy a single file, or rebuild the whole system by swapping a subvolume. Works from a live USB onto a brand-new machine.

⏸️

Pause & resume

A 14-hour first run can be frozen mid-stream and continued from the same byte — from the app or the tray.

🖥️

Native desktop app

A GTK4 / libadwaita window plus a system-tray icon with live status (phase, percent, bytes) and Pause / Resume / Stop.

🕒

Time Machine cadence

Hourly snapshots with 24h / 30d / 12m / 3y retention, scheduled by systemd.

How it works

Snapshots of the system and home subvolumes, sent as deltas to an encrypted drive. Versions are real subvolumes, so the drive is a filesystem you can browse — and hand to a new computer.

  your machine (btrfs, subvols @ and @home, LUKS-encrypted)
        │  btrbk: read-only snapshot  →  btrfs send -p (delta)
        ▼
  backup drive (LUKS + btrfs)
        └─ portal/@.<timestamp>        full tree of the root filesystem
           portal/@home.<timestamp>    full tree of /home
           portal/boot-esp/            the vfat ESP, mirrored
           portal/.timeportal.json     self-describing manifest

Install

Arch and Omarchy — download the package from the latest release and install it with pacman:

# after downloading time-portal-<version>-x86_64.pkg.tar.zst
$ sudo pacman -U time-portal-0.1.0-1-x86_64.pkg.tar.zst

Everything ships in one package: the app, its privileged helper (driven by polkit), the btrbk config, and the systemd units.

Requirements

gtk4  libadwaita  btrbk
cryptsetup  btrfs-progs

From source

$ git clone https://github.com/CurePortal/time-portal
$ cd time-portal
$ cargo build --release
$ sudo ./dev-install.sh

Setting up a backup drive

In the app, Set up a new backup drive lists a spare disk, asks for a passphrase, and does the rest — encrypt, format, mount, schedule. Keep the passphrase somewhere other than this laptop: the keyfile unlocks the drive automatically here, but the passphrase is what opens it on a new machine.
